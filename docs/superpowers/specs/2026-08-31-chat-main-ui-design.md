# LedgerAI 对话主界面（M6-b）设计文档

日期：2026-08-31 · 状态：已与用户确认设计方向，待评审

## 目标

为非专业会计使用者提供一个「对话即记账」的主操作界面：对话框是唯一必须学会的入口，
科目余额表、报表、凭证等模块以表格视图一键查看；凭证卡片同时支持 AI 识别填充与手工新增编辑。

## 技术形态

轻量单页（延续 `/settings` 模式）：单 HTML 文件 + vanilla JS，由后端 `/app` 路径托管，
不引入 Vue/Node 构建链。复用全部现有 API。将来 Vue 前端立项时可参考本页交互。

## 对话流

- 用户消息：文本 + 📎 附件上传（走 `POST /api/ai/parse`）。
- AI 消息三种形态：
  1. 解析结果卡（字段摘要 + 警告标黄）；
  2. **统一凭证确认卡**（见下）；
  3. 纯文本回答（含「查看余额表」等跳转按钮）。
- 输入区：文本框 + 📎 + 发送；快捷问题 chips（本月收入 / 本月费用 / 看看余额表），
  前端关键词路由直接调报表接口拼答（确定性、零 token）；LLM 自由问答列为 M6-c。
- 确认落账后自动追加「✅ 已落账 记字第X号」，并刷新凭证列表 / 余额表 / 右栏概要。

## 统一凭证卡片（三种入口，一条通道）

1. **AI 识别填充**：拖单据 → AI 出候选凭证，字段可继续编辑（`/api/ai/suggest`）；
2. **手动新增**：输入区 [+ 新增凭证] 打开空白卡（日期默认今天，空白分录行）；
3. **混合**：在 AI 卡片上增删行 / 改科目 / 改金额。

卡片要素：凭证日期、附单据数、多行分录（摘要 | 科目搜索下拉（仅启用末级科目，
数据来自 `GET /api/accounts`）| 借方 | 贷方）、底部借方合计/贷方合计/差额
（差额≠0 红色并禁用确认）、📎 电子附件上传。

确认通道：AI 卡 → `POST /api/ai/confirm`（source=ai，自动挂附件、可追溯）；
手动卡 → `POST /api/vouchers`（source=manual，附单据数≥1）。
两条通道校验规则一致：差额≠0 不能确认。

## 模块视图（全部直调现有 API）

| 模块 | 接口 | 视图 |
|---|---|---|
| 凭证 | GET /api/vouchers | 列表 + 状态筛选；审核/过账按钮按角色显示（auditor/admin） |
| 科目余额表 | GET /api/reports/trial-balance | 六栏表 + 合计行 + 平衡徽标 |
| 利润表 | GET /api/reports/income-statement | 本月/本年累计两列 |
| 资产负债表 | GET /api/reports/balance-sheet | 期末/年初两列 |
| 发票 | GET /api/invoices | 列表（方向/状态筛选） |
| 报税 | GET /api/tax/reminders、/api/tax/vat | 到期提醒 + 本季测算卡 |

期间选择器全局联动所有视图与对话上下文。

## 权限

登录制单账号（bookkeeper）可对话 + 确认落账 + 填卡；
审核/过账按钮仅对 auditor/admin 显示；模型配置页仅 admin（沿用 /settings）。

## 错误处理

- 401：自动清除本地 token 并弹出登录卡；
- LLM 失败：透传网关原始错误信息（便于诊断 Key/套餐）；
- 确认失败：显示后端返回的具体校验原因（借贷不平/科目停用等）。

## 测试策略

后端已有 134 个测试保障接口正确性；页面采用手动验收清单
（登录→AI 单据→编辑→确认→余额表刷新→手工卡→审核过账），
每个验收点对应一个 API 已有测试。

## 明确不做（本版）

- LLM 工具调用自由查账（M6-c：网关加 tool schema）；
- 凭证打印/PDF（M4 已列可选）；
- 多账套切换（单账套假设不变）。
