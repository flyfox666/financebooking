代码审查确认的额外风险

以下结论基于控制流、数据模型与调用位置。潜在串卡、迟到响应和脚本执行尚未做完整浏览器攻击或并发复现，不与上述实测混为一谈。

S01 · 切账套没有清理真正的 AI 历史 高

switchBook/createNewBook 仅清 chatLog，未清 CHAT_HISTORY、pendingAsk、cardState；agentChat 继续提交全局 CHAT_HISTORY。还缺异步响应与发起账套的绑定。

建议：清理会话全状态；每次请求固定 book_id 与会话版本，切换时取消旧请求/丢弃迟到结果。

backend/app/static/app.html:191、230、522、590

S02 · 多张候选卡共享一个全局状态 高

showCard 每次覆写 cardState，卡片重复使用 vcCard ID；confirmCard 读取全局候选及首个 DOM 卡片。多票同图会连续 showCard，存在确认错卡风险。

建议：每张卡片用独立 candidate_id、状态、日期、按钮和请求，完成后禁用，支持多卡同时待确认。

backend/app/static/app.html:473、475、629

S03 · 用户/模型文本直接进入 HTML 高

addBubble 使用 innerHTML；用户输入、解析字段、模型回复和部分名称未经统一转义。当前确认的是不安全渲染路径，未执行恶意脚本。

建议：普通文字使用 textContent；界面卡片与外部文字分离，必要富文本使用白名单净化；覆盖名称、摘要、文件名。

backend/app/static/app.html:330、334

S04 · 备份不包含原始单据 高

run_backup_now 只备份 SQLite 为 db.gz；附件在独立目录，调度器失败被吞掉。复制备份库不能恢复原件。Windows 关机/关程序期间也不会执行凌晨任务。

建议：提供数据库+附件清单与文件的一致备份包、备份结果提示、启动补备份和恢复演练；保留当前 SQLite 在线备份机制。

backend/app/core/backup.py:35；backend/app/main.py:backup_scheduler

S05 · 模型密钥未按文档加密存储 高

LLMProvider.api_key 是直接写入与读取的字符串，当前模型配置复用也确认这一路径；报告未读取或输出密钥值。

更贴近使用者的改进

1. 用“待办工作台”串起日常工作

首页按“待识别、待补资料、待确认、待审核、待处理差异、月末未完成”分组，点开就能处理。非专业人员无需先判断该去发票、凭证还是报表页面。

验收：新用户上传一张单据后，能看见现在处于哪一步、下一步由谁做、缺什么资料；处理中断或刷新后仍可恢复。

2. 优先建设统一票据池和原件资产

文件先归档，解析任务与业务单据分别记录状态；一份文件可以包含多张票，一张票也可关联多份证据。发票、付款记录、合同按同一笔业务关联，减少把“发票+付款截图”重复记两次的机会。

验收：批量上传、多页 PDF、一图多票、解析失败、重复上传和重试均有明确状态；每个已确认凭证可回看对应原件。

3. 候选确认页同时展示原件和依据

左侧原件/定位页，右侧分录；日期、金额、方向、科目和税额可看到来源。系统修正字段高亮；疑似重复、票面金额差异、缺附件必须给出明确处理选择。区分“生成草稿”“提交审核”“审核通过”“过账”，避免“落账”使人误以为已经进入正式报表。

4. 把月末和恢复能力做成可完成的流程

月末列出未过账凭证、缺原件、勾稽差异、结转与备份状态，逐项处理再结账。提供完整备份导出、恢复到新测试环境与附件哈希核验；桌面启动显示实际版本、端口和数据位置。

5. 收拢业务规则，保留轻量架构

继续使用当前单体结构；将权限、确认事务、发票身份、期间校验与候选风险收敛为共享服务，逐步拆分 app.html 中的会话、卡片和票据模块。小规模与一般纳税人能力分别验收，税务结果带期间、参数和数据来源；本轮未做现行税法正确性审计。

建议实施顺序与完成标准

  1. 第一批：安全与账务边界。R01、R02、R08、R09，连同 S01、S03。完成标准：跨账套写操作全部拒绝；编辑者不能审核本人修改版本；失败不留半成品；重试/并发不重复；切换账套不带历史上下文；外部文本按文字显示。
  2. 第二批：发票、附件与现金流闭环。R03–R07、R10–R13，建设服务端风险确认。完成标准：正反方向、同号不同方向、多票共原件、红字、净零收支、用户拒绝重复、非法模型数据均有独立业务预期用例。
  3. 第三批：可恢复、可交付。完整备份、恢复演练、密钥迁移、首启引导、端口身份校验与安装包验收。完成标准：在另一空环境恢复后账簿金额一致、每份原件哈希一致、旧环境未受影响。
  4. 第四批：提升日常效率。票据池、原件对照、待办工作台与月末向导；在前述正确性基础上扩展多页 PDF、批处理和一般纳税人场景。
